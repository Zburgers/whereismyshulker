# Where Is My Shulker — Minecraft 26.2 Implementation Plan

**Status:** ready for one implementation agent  
**Research date:** 2026-09-08  
**Companion spec:** `docs/26.2-migration-spec.md`  
**Research audit:** `docs/26.2-research-audit.md`  
**Shipyard handoff:** `docs/26.2-shipyard-handoff.md`  
**Code baseline:** `CODE_BASE_SHA=29ec55b5d8c6da614764d33da95378ec42a0d99b`  
**Target:** Minecraft `26.2`, Fabric, Java `25`

This plan is intentionally executable rather than aspirational. Work in order. Each phase has a bounded change, verification command, acceptance condition, and suggested commit checkpoint.

---

## 0. Delivery contract

Deliver one coherent implementation branch/PR that ports the existing mod to Minecraft 26.2 without changing its client-only deployment model.

### Preserve

- client-only operation on singleplayer and arbitrary multiplayer servers;
- no server-side installation requirement;
- existing singleplayer and multiplayer CSV locations;
- six/seven-column historical row readability;
- `/shulker`, `/shulker <page>`, `/shulker clear`, `/shulker clearall`;
- pagination, names, colors, dimensions, direction/distance, hover text and coordinate suggestions;
- placement recorded only after vanilla placement succeeds.

### Change deliberately

- Yarn/remapping-era source vocabulary → Mojang/official names;
- Java 21 → 25;
- old build model → non-obfuscated 26.2 Loom;
- break Mixin → `ClientPlayerBlockBreakEvents.AFTER`;
- shutdown-only cleanup → `ClientPlayConnectionEvents.DISCONNECT`;
- fuzzy command parser → explicit Brigadier tree;
- destructive commands → attended;
- removal key → dimension + position;
- custom-name parser → comma-safe final column;
- translation-key color parsing → `ShulkerBoxBlock.getColor()`;
- empty main initializer/mixin scaffolding → removed.

### Do not add

- server networking/state;
- GUI/renderer/waypoints;
- broad persistence redesign;
- registry objects;
- new user-facing features;
- unrelated refactors.

## I3. HEAD: snapshot custom name before vanilla placement mutates stack

```java
@Inject(method = "place", at = @At("HEAD"))
private void whereismyshulker$captureName(
        BlockPlaceContext context,
        CallbackInfoReturnable<InteractionResult> cir) {
    Level level = context.getLevel();
    if (!level.isClientSide()) return;

    BlockItem self = (BlockItem) (Object) this;
    if (!(self.getBlock() instanceof ShulkerBoxBlock)) return;

    Component name = context.getItemInHand().getCustomName();
    whereismyshulker$pendingCustomName.set(name == null ? "" : name.getString());
}
```

Use the exact 26.2 public member names if the target source differs; preserve semantics.

## I4. RETURN: record only successful final shulker placement

Target semantic code:

```java
@Inject(method = "place", at = @At("RETURN"))
private void whereismyshulker$onPlace(
        BlockPlaceContext context,
        CallbackInfoReturnable<InteractionResult> cir) {
    try {
        InteractionResult result = cir.getReturnValue();
        if (result == null || !result.consumesAction()) return;

        Level level = context.getLevel();
        if (!level.isClientSide()) return;

        BlockItem self = (BlockItem) (Object) this;
        if (!(self.getBlock() instanceof ShulkerBoxBlock)) return;

        BlockPos pos = context.getClickedPos();
        BlockState state = level.getBlockState(pos);
        if (!(state.getBlock() instanceof ShulkerBoxBlock)) return;

        ShulkerBoxTracker.getInstance().onShulkerBoxPlaced(
            pos,
            state.getBlock(),
            level,
            whereismyshulker$pendingCustomName.get()
        );
    } finally {
        whereismyshulker$pendingCustomName.remove();
    }
}
```

Do not remove the final state check. It protects against recording failed/redirected placement assumptions.

# 16. Failure policy for the implementation agent

When a specific 26.2 member named in this plan does not compile:

1. open the exact class from Loom-generated Minecraft 26.2 sources or the Fabric API source/Javadocs;
2. find the public member with the specified semantics;
3. use the smallest correct target equivalent;
4. do not introduce reflection, an access widener, or another Mixin merely to avoid resolving an API;
5. preserve the spec invariant;
6. record the actual resolved member in the implementation notes.

When a Mixin compiles but fails at runtime:

1. inspect exact 26.2 `BlockItem.place` descriptor/source;
2. correct target/handler signature;
3. keep `defaultRequire=1`;
4. rerun startup and placement matrix;
5. never suppress the injection error.

When historical data does not load:

1. stop before writing over the file;
2. compare path resolution and row parsing to `CODE_BASE_SHA`;
3. fix compatibility rather than inventing a new storage path/schema.
