## 4. Protected product invariants

Treat these as tests, not preferences.

### P1 — client-only

Do not add server entrypoints, custom server networking, server state or an installation requirement.

### P2 — storage compatibility

Keep:

```text
singleplayer: <world>/data/shulker_boxes.csv
multiplayer:  .minecraft/.whereismyshulker/<sanitized-server-address>/shulker_boxes.csv
```

Keep the existing server-address sanitizer.

### P3 — row compatibility

Keep:

```text
x,y,z,dimension,color,timestamp,customName
```

Continue accepting old 6-column rows.

### P4 — successful-placement semantics

Do not record a placement merely because the user attempted one. Record only after vanilla reports successful interaction and a shulker block actually exists at the contextual placement position.

### P5 — custom source name

Capture the source stack custom name before vanilla placement can mutate/decrement it.

### P6 — dimension-safe identity

Removal identity is:

```text
dimension + BlockPos
```

not `BlockPos` alone.

### P7 — session isolation

JOIN loads. DISCONNECT clears. Client shutdown alone is insufficient.

### P8 — command safety

Every command branch that mutates persisted history must require:

```java
FabricClientCommandSource::attended
```

### P9 — coordinate click safety

Coordinates suggest `/tp`; they never auto-run it.

### P10 — minimal Mixins

The break Mixin is deleted. The placement Mixin is the only remaining low-level patch.

## 13. Runtime debugging lenses

### If placement does not track

Inspect in this order:

1. Mixin startup log/injection count;
2. exact `BlockItem.place` method descriptor;
3. result's success predicate;
4. contextual target position;
5. final `BlockState` check;
6. tracker path/state loaded for current session.

Do not immediately add another event/Mixin.

### If placement duplicates

Check whether:

- RETURN injection fires more than once;
- another hook was accidentally retained;
- list is loaded/re-appended incorrectly;
- contextual position changes during one use.

### If break does not remove

Check:

- `ClientPlayerBlockBreakEvents.AFTER` registration;
- provided pre-break state is shulker;
- canonical dimension string equals persisted row;
- exact `BlockPos` equality.

Do not reintroduce interaction-manager Mixin before proving Fabric event cannot meet the spec.

### If history is empty after reconnect

Before modifying the file:

1. print/log resolved `csvFilePath` locally during debugging;
2. compare to historical location;
3. inspect actual file;
4. test row parser;
5. ensure DISCONNECT cleared state but JOIN loaded the new session.

Do not write a migration to a new directory.

### If commands fail

Separate:

- Brigadier registration/tree issue;
- `attended()` requirement issue;
- component constructor/API issue;
- empty tracker/session issue.

Do not fall back to fuzzy string dispatch.
